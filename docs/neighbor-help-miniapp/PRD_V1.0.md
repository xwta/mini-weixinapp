# 社区邻里互助小程序产品文档 V1.0

## 1. 产品基本信息

### 1.1 产品名称

暂定名称：**邻里帮帮**

备选名称：小区帮手、社区帮帮站、邻里小跑腿、懒人生活站、小区万能帮。

### 1.2 产品定位

面向小区居民的本地生活服务小程序，围绕「帮取快递、送水上楼、代扔垃圾、代买取餐、清洁维修预约」等高频生活需求，连接用户、接单员、社区商家和平台后台，实现小区内的即时服务交易闭环。

一句话定位：**不想下楼的小事，都有人帮你跑。**

### 1.3 产品形态

- 用户端：微信小程序
- 接单端：同一个微信小程序内切换身份
- 商家端：第一版可由平台后台代管理，后续再独立开放
- 平台端：Web 管理后台

---

## 2. 项目背景

大量小区居民存在即时生活服务需求，例如不想下楼取快递、搬水上楼困难、上班族没时间买早餐、老人家庭需要简单代办服务等。

传统跑腿平台覆盖范围大，但对于小区内 3 到 10 元的小额服务响应不够灵活，服务成本偏高。小区场景天然具备距离短、需求频繁、信任关系更容易建立的特点，适合做轻量化社区服务平台。

如果平台方已有水站资源、腾讯地图旺店资源、小程序销售资源，可以把本产品包装为：

**水站增值服务入口 + 社区生活服务平台 + 本地商家私域订单工具。**

### 第一阶段目标

- 跑通用户下单、接单员接单、服务完成、平台结算的完整闭环
- 在 1 个小区内验证真实订单需求
- 优先完成 50 到 100 单测试订单
- 找到最高频的 2 到 3 个服务类目
- 建立第一批接单员和合作商家资源

## 3. 目标用户分析

### 3.1 下单用户

| 用户类型 | 典型需求 | 产品切入点 |
|---|---|---|
| 上班族 | 没时间取快递、买早餐、处理琐事 | 快速下单、预约时间 |
| 宝妈 | 带娃不方便下楼 | 帮取快递、代买日用品 |
| 独居年轻人 | 懒人需求强、愿意为便利付费 | 代扔垃圾、取餐、取奶茶 |
| 老人家庭 | 搬重物、维修、送水需求 | 送水上楼、维修预约 |
| 租户 | 对周边服务不熟悉 | 服务分类清晰、价格透明 |
| 高层住户 | 下楼成本高 | 小区内即时跑腿 |

用户痛点：快递站远、水桶重、工作忙、维修清洁找人麻烦、小区商家信息分散、微信群下单容易漏单、服务价格不透明。

### 3.2 接单员

| 接单员类型 | 特点 | 适合服务 |
|---|---|---|
| 小区兼职人员 | 熟悉小区，距离近 | 快递、垃圾、代买 |
| 水站配送员 | 已有配送能力 | 送水上楼、顺路跑腿 |
| 快递站人员 | 掌握快递资源 | 帮取快递 |
| 保洁阿姨 | 有服务经验 | 清洁、代扔垃圾 |
| 维修师傅 | 技能型服务 | 水电维修、家电维修 |
| 附近商家员工 | 有固定门店 | 取餐、商品配送 |

接单员需求：利用碎片时间赚钱、附近接单、不跑远单、收入透明、提现方便。

### 3.3 合作商家

商家类型：水站、早餐店、便利店、水果店、干洗店、家政店、维修店、宠物店、快递驿站。

商家价值：获得小区精准订单、增加复购、降低线上化成本、从单纯门店变成社区服务节点。

## 4. 产品核心价值

### 对用户

- 小事有人帮，减少下楼和等待成本
- 价格透明，服务标准统一
- 下单方便，微信内即可完成
- 订单可追踪，售后有入口
- 小区内服务，响应更快

### 对接单员

- 小区附近接单，距离短
- 碎片时间变现
- 收入可查看，可提现
- 服务类型灵活选择

### 对商家

- 获得小区精准订单
- 增加复购和曝光
- 降低线上化成本
- 从单纯门店变成社区服务节点

### 对平台

- 每单抽佣
- 商家入驻费
- 广告位收入
- 会员收入
- 服务系统费
- 可复制多个小区

### 9.1 接单员认证

字段：姓名、手机号、身份证号、身份证照片、服务小区、可接服务、收款账户。

认证状态：未认证、审核中、已通过、已驳回、已冻结。

字段：服务类型、用户地址、用户备注、联系用户按钮、导航/位置说明、预计收入、完成服务按钮、上传凭证。

结算规则：用户确认完成后，接单员收入进入可提现余额；平台可设置 T+1 或 T+3 提现；投诉订单暂缓结算。

## 11. 核心业务流程

### 11.1 用户下单流程

用户进入小程序 → 选择当前小区 → 选择服务类型 → 填写服务信息 → 系统计算价格 → 用户确认订单 → 微信支付 → 订单进入待接单 → 接单员抢单或后台派单 → 接单员完成服务 → 上传完成凭证 → 用户确认完成 → 平台结算 → 用户评价。

### 11.2 接单员抢单流程

接单员进入接单大厅 → 查看可接订单 → 点击抢单 → 系统锁定订单 → 接单员联系用户 → 完成服务 → 上传凭证 → 等待用户确认 → 收入进入余额 → 接单员申请提现。

### 11.3 平台派单流程

适合服务：送水、维修、清洁。

用户支付订单 → 后台收到待派单提醒 → 管理员选择接单员/商家 → 接单员确认接单 → 完成服务 → 用户确认 → 平台结算。

### 11.4 订单取消规则

- 用户未支付：可直接取消
- 已支付但无人接单：可申请取消，系统自动退款或平台审核退款
- 接单员已接单：按规则判断是否扣除部分费用
- 接单员已完成：不可直接取消，进入售后流程

## 12. 订单状态设计

| 状态 | 说明 |
|---|---|
| 待支付 | 用户已提交订单但未付款 |
| 待接单 | 用户已支付，等待接单员接单 |
| 已接单 | 接单员已抢单/后台已派单 |
| 服务中 | 接单员正在服务 |
| 待确认 | 接单员已完成，等待用户确认 |
| 已完成 | 用户确认完成或系统自动完成 |
| 已取消 | 用户/平台取消订单 |
| 退款中 | 用户申请退款 |
| 已退款 | 退款完成 |
| 投诉中 | 用户发起投诉 |

正常状态流转：待支付 → 待接单 → 已接单 → 服务中 → 待确认 → 已完成。

异常流转：待支付 → 已取消；待接单 → 已取消/退款中；已接单 → 退款中/投诉中；待确认 → 投诉中/已完成。

## 13. 支付与结算设计

第一版支持微信支付。

订单金额 = 基础服务费 + 加价费用 + 商品费用 - 优惠金额。

加价费用包括：加急费、多件费、楼层费、距离费、夜间服务费。

用户支付后，款项先进入平台账户。订单完成后，接单员获得服务分成，平台获得抽佣，如涉及商家，商家获得商品/服务收入。

提现建议：最低提现 10 元，提现周期 T+1 或 T+3，投诉订单冻结结算，平台人工审核提现。

## 14. 风控规则

### 用户侧

- 必须绑定手机号后才能下单
- 取件码等隐私信息仅对接单员展示
- 用户恶意取消可限制下单
- 投诉过多用户可进入黑名单

### 接单员侧

- 接单员必须实名认证
- 接单员需通过平台审核
- 接单后超时未处理扣信用分
- 投诉成立扣款/冻结账户
- 严重违规永久封禁

### 服务边界

第一版建议明确禁止：贵重物品代取、违法物品代买、药品烟酒等限制类商品代买、大额垫付、无授权进入用户家中、宠物寄养等高风险服务。

### 帮取快递规则

用户主动提供取件码，即视为授权代取。贵重快递建议用户自行领取。接单员完成后需拍照留存。如快递损坏，需根据凭证判定责任。

## 15. 运营设计

### 15.1 冷启动方式

第一阶段优先选择一个小区测试。

推荐小区特征：住户多、快递站距离住宅楼较远、年轻人多、有物业/业主群资源、周边有水站早餐店便利店、小区群活跃。

冷启动动作：建立小区微信群，快递站门口放宣传海报，电梯口/公告栏放二维码，首单优惠，招募小区兼职接单员，与水站/早餐店合作，做 7 天试运营活动。

### 15.2 第一批服务建议

先主推：帮取快递、送水上楼、代扔垃圾。

### 15.3 首单活动设计

活动名称：懒人下楼解放计划。

规则：新用户首单立减 3 元，邀请好友下单得 2 元优惠券，接单员完成前 10 单奖励 10 元，水站合作用户送优惠券。

### 15.4 用户增长方式

小区群推广、微信朋友圈海报、快递站二维码、水站桶贴二维码、商家收银台二维码、首单优惠券、老带新优惠、小区公告栏。

## 16. 数据指标

| 指标 | 说明 |
|---|---|
| 注册用户数 | 小程序注册人数 |
| 下单用户数 | 实际下单人数 |
| 订单数 | 总订单量 |
| 支付转化率 | 提交订单到支付的比例 |
| 接单率 | 有人接单的订单比例 |
| 完成率 | 已完成订单占比 |
| 复购率 | 多次下单用户占比 |
| 客单价 | 平均每单金额 |
| 平台收入 | 抽佣和服务费收入 |
| 投诉率 | 投诉订单占比 |

MVP 验证标准建议：7 到 14 天内，注册用户 ≥ 100 人，完成订单 ≥ 50 单，接单率 ≥ 80%，完成率 ≥ 90%，投诉率 ≤ 5%，复购用户 ≥ 10 人，至少 3 名稳定接单员。

## 20. 产品卖点话术

### 对用户

快递不用自己跑，水不用自己搬，垃圾不用自己扔，小区里的生活小事，一键找人帮忙。

### 对接单员

在小区附近接单，利用空闲时间赚钱，不用跑远路，完成一单赚一单。

### 对商家

让门店进入小区居民手机里，早餐、水、维修、清洁都可以线上接单，提高复购和曝光。

### 对水站

不只是卖水，而是升级成小区生活服务站。客户买水时能顺便下单其他服务，水站从单一业务变成社区入口。

## 22. 当前建议结论

第一版不要做“大而全”的社区平台，而是做一个小区内能真实跑单的轻量交易系统。

最小可行版本只需要围绕三件事：用户能下单并支付、接单员能接单并完成、平台能管理订单并结算。

优先服务建议：帮取快递、送水上楼、代扔垃圾、取餐代买。
