## 4. 第一版推荐服务类目

| 服务 | 是否第一版上线 | 说明 |
|---|---|---|
| 帮取快递 | 是 | 高频、低成本、易验证 |
| 送水上楼 | 是 | 与水站资源匹配 |
| 代扔垃圾 | 是 | 高频小额服务 |
| 取餐/取咖啡 | 是 | 用户理解成本低 |
| 商品代买 | 可选 | 需要限制垫付风险 |
| 清洁预约 | 可选 | 可由后台派单 |
| 维修预约 | 可选 | 需资质和售后规则 |
| 宠物服务 | 否 | 风险较高，放后期 |
| 社区团购 | 否 | 供应链复杂，放后期 |

## 5. 订单状态

- 待接单

- 已取消

## 6. 开发优先级建议

### 第一周：需求和原型

- 确认服务类目
- 确认小区场景
- 画用户端原型
- 画接单端原型
- 画后台原型
- 确认订单状态和价格规则

### 第二到第三周：核心功能开发

- 登录/小区/首页
- 服务下单
- 订单系统
- 微信支付
- 接单大厅
- 抢单流程

### 第四周：后台和结算

- 订单后台
- 接单员审核
- 服务类目管理
- 提现记录
- 退款投诉

### 第五周：测试和上线

- 小区真实测试
- 修复流程问题
- 设置服务价格
- 招募接单员
- 上线第一个小区

---

## 7. MVP 验证指标

7 到 14 天测试目标：

- 注册用户 ≥ 100 人
- 完成订单 ≥ 50 单
- 接单率 ≥ 80%
- 完成率 ≥ 90%
- 投诉率 ≤ 5%
- 复购用户 ≥ 10 人
- 稳定接单员 ≥ 3 人

达到以上指标后，再考虑商家端、会员、广告位和多小区复制。
